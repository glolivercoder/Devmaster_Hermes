Para o seu caso, o substituto local mais indicado é o Gitea (go-gitea/gitea). Ele é leve, roda bem em um mini PC/VPS, oferece interface web, repositórios Git, API REST, webhooks, issues, releases, usuários/organizações e backup integrado — praticamente um “GitHub básico self-hosted”.

Recomendação principal
Opção	Quando escolher
Gitea	Melhor equilíbrio: leve, simples, API completa, webhooks, Actions e backup nativo. Ideal para backup, versionamento e endpoints de automação. 
Forgejo	Fork comunitário do Gitea, muito parecido; escolha se preferir governança comunitária e ecossistema Forgejo. Tem API, webhooks, registry e Actions compatíveis com GitHub Actions. 
GitLab CE	Só se você quiser CI/CD, container registry, segurança e recursos empresariais mais pesados; consome muito mais RAM.
Git bare + rsync/Borg	Se quiser apenas backup simples, sem interface, API ou automação.
Para múltiplos webapps/SaaS e integração com agentes, Gitea é a melhor escolha.

Por que Gitea atende seus requisitos
Versionamento local: repositórios Git privados, branches, tags, releases, pull requests e histórico completo.

Endpoints/API: a API REST cobre cerca de 300 operações para repositórios, branches, commits, PRs, issues, releases, webhooks, organizações, usuários e administração.

Webhooks: dispara eventos de push, PR, issue, release e pacote para n8n, seu backend, LiteLLM, CI ou agentes.

CI/CD: Gitea Actions é compatível com workflows no estilo GitHub Actions, usando .gitea/workflows/.

Backup: o comando gitea dump gera um arquivo ZIP/TAR com banco de dados, repositórios, LFS e dados da instalação.

Proteção contra erros: branches protegidas, PRs obrigatórios, revisão, tags de release e histórico imutável permitem voltar a qualquer versão estável.

Instalação mínima com Docker
text
services:
  gitea:
    image: gitea/gitea:latest
    container_name: gitea
    restart: unless-stopped
    environment:
      USER_UID: "1000"
      USER_GID: "1000"
      GITEA__server__DOMAIN: git.seudominio.local
      GITEA__server__ROOT_URL: https://git.seudominio.local/
    volumes:
      - ./gitea-data:/data
      - /etc/timezone:/etc/timezone:ro
      - /etc/localtime:/etc/localtime:ro
    ports:
      - "3000:3000"
      - "2222:22"

  postgres:
    image: postgres:16
    container_name: gitea-db
    restart: unless-stopped
    environment:
      POSTGRES_USER: gitea
      POSTGRES_PASSWORD: troque-esta-senha
      POSTGRES_DB: gitea
    volumes:
      - ./postgres-data:/var/lib/postgresql/data
Depois acesse http://localhost:3000 e configure o administrador inicial.

Backup automático
O backup nativo inclui banco, repositórios e dados da instância em um único arquivo.

bash
docker exec -u git gitea \
  gitea dump -c /data/gitea/conf/app.ini \
  --file /data/backups/gitea-$(date +%F).zip
Para rodar diariamente às 3h:

bash
crontab -e
text
0 3 * * * docker exec -u git gitea gitea dump -c /data/gitea/conf/app.ini --file /data/backups/gitea-$(date +\%F).zip
Regra importante: nunca deixe o backup apenas no mesmo disco/servidor. Copie para um HD externo, NAS, Backblaze B2, S3, Wasabi ou outro local. O dump do Gitea é restaurável, mas a restauração é manual: você extrai o arquivo e recupera banco, repositórios e arquivos de configuração.

Endpoint para seus projetos
Você pode expor endpoints como:

text
POST /api/v1/repos/{owner}/{repo}/hooks
GET  /api/v1/repos/{owner}/{repo}/commits
GET  /api/v1/repos/{owner}/{repo}/branches
POST /api/v1/repos/{owner}/{repo}/issues
POST /api/v1/repos/{owner}/{repo}/releases
Exemplo de webhook para avisar seu backend ou n8n após um push:

bash
curl -X POST "https://git.seudominio.local/api/v1/repos/gleidson/meu-webapp/hooks" \
  -H "Authorization: token SEU_TOKEN_GITEA" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "gitea",
    "config": {
      "url": "https://api.seudominio.com/webhooks/gitea",
      "content_type": "json"
    },
    "events": ["push", "pull_request", "issue"],
    "active": true
  }'
O Gitea envia payloads JSON nesses eventos, permitindo que seu agente de desenvolvimento, pipeline de deploy ou sistema de auditoria reaja automaticamente.

Proteção contra erros
Configure isto em cada repositório:

Branch principal protegida: main ou master sem push direto.

PR obrigatório: pelo menos uma aprovação para mudanças em produção.

CI antes do merge: testes, lint, build e security scan.

Tags semânticas: v1.0.0, v1.1.0, etc.

Releases: artefatos versionados e changelog.

Backup diário + retenção: manter 7 diários, 4 semanais e 6 mensais.

Espelho para outro servidor: use git push --mirror ou o mirror do Gitea para uma segunda máquina.

text
Seus projetos
   │
   ├── Gitea local — fonte da verdade, PRs, issues, releases
   ├── Gitea Actions — testes, build, lint e deploy
   ├── Webhooks — disparam n8n, backend, agentes e deploy
   ├── LiteLLM — chaves e custos de LLM
   └── Backup externo — B2/S3/NAS/HD externo
Se quiser o caminho mais simples e robusto: Gitea + PostgreSQL + Gitea Actions + backup diário externo. Isso cobre versionamento, endpoints, automação, rollback e proteção contra erros sem o peso do GitLab
